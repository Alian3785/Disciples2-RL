# Лаборатория стража столицы

`scripts/guardian_lab.py` автоматически ищет составы отряда и тактики против
стража вражеской столицы на общей JAX-среде NumberGrid. Первая цель —
Мизраэль на Default Capital (`load_map('default-capital')`, отряд с индексом
74, в интерфейсе «отряд №75»). Инструмент обобщает ручные Монте-Карло-скрипты
`results/mizrael-party-sim-*` и не меняет правила среды.

Сценарные тактики — проверка среды, а не политика агента: их действия
никогда не передаются обучению (AGENTS.md).

## Конвейер

```
capabilities → candidates → screen (биномиальная оценка + цепь Маркова) → cost / archive → simulate (GPU)
```

Статические подкоманды (`capabilities`, `candidates`, `screen`, `cost`,
`archive`) читают карту, `units.json`, `buildings.json` и каталоги модулей
среды. Они импортируют модули JAX, но не создают массивов на устройстве и не
занимают GPU; нужен venv проекта. `simulate` работает только на CUDA через
`scripts/run_gpu.sh`.

### Команды

Статика (venv проекта в WSL; `run_gpu.sh` задаёт `PYTHONPATH` и
`XLA_PYTHON_CLIENT_PREALLOCATE=false`, статические подкоманды GPU не трогают):

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py capabilities --output results/guardian-lab/capabilities.json
```

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py candidates --hero-levels 4-8 --output results/guardian-lab/candidates.json
```

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py screen --hero-levels 4-8 --markov-top 200 --expand-top 10 --export 30 --with-cost --output results/guardian-lab/screen.json
```

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py cost --tactics results/guardian-lab/screen.json --top 10
```

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py archive --hero-levels 4-8 --output results/guardian-lab/archive.json
```

Один состав без генератора (шесть слотов, `-` — пусто; большой боец занимает
передний слот и пустой задний):

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py screen --roster infernal_knight,duke,infernal_knight,incubus,incubus,incubus --hero-level 6
```

GPU-моделирование лучших тактик экрана (только по отдельному запросу
пользователя, без конкурирующих GPU-задач):

```bash
bash scripts/run_gpu.sh scripts/guardian_lab.py simulate --tactics results/guardian-lab/screen.json --top 20 --sims 2048 --trace 1 --output results/guardian-lab/sim-20261019
```

Общие ключи всех подкоманд: `--map` (по умолчанию `default-capital`) и
`--guardian` (индекс отряда; по умолчанию цель карты или страж столицы).
`--wounds N` задаёт уже снятые с стража HP — для оценки второго боя того же
дня (см. «Раны между боями»).

### capabilities

Профиль стража: HP, урон, источник и охват атаки, попадание по паре бросков,
броня + бонус столицы и действующий предел 90%, инициатива, иммунитеты к
источникам и защиты, иммунитеты к классам атак из `units.json`
(`attack_class_immunities`, GImmuC), восстановление за отдых, опыт за убийство.
Затем — каждый достижимый для фракции боец (найм, цепочки улучшений,
наёмники) против стража: удары до гибели (обычные, с Эликсиром неуязвимости,
после ослабления), урон за ход, контроль (паралич/окаменение/страх, основной
или вторичной атакой, артефакты героя), DoT, ослабление, порядок хода
относительно стража, стоимость зданий. В конце — рейтинги контроля, DoT,
урона на единицу лидерства и выживаемости, зелья, снаряжение, боевые
предметы и заклинания-усиления фракции с их доступностью на карте.

### candidates

Перебор мультимножеств бойцов при ограничениях:

- лидерство героя: 3 места, +1 на 3-м и 6-м уровне, не более 5; большой боец
  занимает 2; по умолчанию отбрасываются составы, оставляющие 2 места и больше
  (`--include-partial` возвращает их);
- размещение найма: герой в своём стартовом слоте, малые бойцы ближнего боя —
  в свободные передние слоты, остальные — назад, большой — передний слот с
  пустым задним;
- здания: замыкание требований каждой формы и взаимоисключения
  `buildings.json` (с потомками исключённых зданий), `blocked_buildings`,
  `max_building_level`; наёмники — в пределах запаса лагеря;
- пул по умолчанию — конечные формы фракции и наёмники (`--pool all` — все
  достижимые формы, `--units` — явный список);
- зелья и предметы — только имеющиеся на карте (сундуки, руины, лавки);
- экипировка героя — автовыбор среды по цене с требованиями навыков
  (знамя с 7-го, сапоги с 8-го, книга с 11-го уровня; артефакты у воина сразу);
- сферы и талисманы — с 10-го уровня героя, у лорда-мага или с книгой;
  в бою два слота, одна экипировка в день: план «экипировка, отдых,
  экипировка, затем временные зелья».

План зелий по умолчанию: зелья выживания — контролёрам, затем герою и
бойцам, если добавляют удар до гибели (остаток — герою); все зелья урона —
бойцу с наибольшим приростом урона основной атаки (тик DoT и шанс вторичных
эффектов зелья не меняют, правило `dot_potions`); точность — контролёру с
основной атакой контроля, иначе бойцу;
инициатива — герою; защиты стихий — только при совпадении с источником
стража. Боевые предметы: ослабление и страх, если есть; при контролёрах —
воскрешение; затем лучшее лечение. Правила применения: контролёры, герой,
бойцы; Life — павшему, лечение — раненому, которого следующий удар убьёт,
если после полного лечения он переживёт удар (иначе лимит 0: только
воскрешение). Предметы первого хода (ослабление, страх, призыв, сферы урона)
идут первыми.

### screen

Две оценки для каждого кандидата:

1. **Биномиальная формула** из задачи:
   P ≈ Σ_{j≤k} C(R−1, j)·q^j·(1−q)^(R−1−j), где q — шанс, что все живые после
   первого удара контролёры промахнутся за раунд (точность по паре бросков,
   вторичный эффект — произведение двух попаданий); R — раундов до снятия HP
   стража при среднем уроне за раунд с бронёй, точностью и DoT; k — лишние
   удары, которые отряд переносит без потери контролёра. Поле `formula` —
   сумма как есть, `p` — то же с q = 1 после 40-го раунда для паралича и
   окаменения.
2. **Цепь Маркова** по раундам: состояние — история ударов (обычные и после
   ослабления), состояние паралича стража (короткий флаг, возраст длительного),
   оставшееся HP корзинами по `--hp-bin` (5). Порядок раунда: бойцы быстрее
   стража, тики DoT, удар стража (если не пропускает), остальные бойцы, их
   контроль и ослабление на следующий раунд. Живые бойцы для каждой истории
   ударов берутся из детерминированной хронологии HP со средним уроном удара и
   предметами героя (не больше одного между ударами). Выход: победа,
   поражение, таймаут 75 раундов, средний раунд победы.

Цепь считается для `--markov-top` лучших по формуле. Для `--expand-top`
лучших составов дополнительно перебираются получатели неуязвимости,
получатель зелий урона и все пары боевых предметов. `--export` пишет лучшие
тактики в формате `simulate` вместе с правилами и списком проверок.

### cost

Формулы стоимости развития —
[UNITS.md](UNITS.md#progression), [ECONOMY.md](ECONOMY.md#sites),
[UNITS.md](UNITS.md#duke):

- пороги опыта по цепочке формы (`exp_required`; у героя 150 + 500 за уровень;
  у конечной формы каждый лишний уровень — тот же порог);
- фонд опыта — сумма `exp_kill` всех армий карты, кроме стражей
  (Default Capital: 11 916); делится поровну между текущими членами отряда,
  включая уже достигших цели;
- найм по мере роста лидерства: стартовые бойцы переиспользуются по корню
  цепочки, остальные нанимаются, как только хватает мест (раньше —
  с наибольшей потребностью в опыте), лишние стартовые увольняются;
- недостающий опыт — у тренера по `TRAINING_C` формы (герой первым: его
  уровни открывают места);
- золото: здания (замыкание требований), найм (`ENROLL_C`, цена лагеря),
  тренер, покупки в лавке сверх бесплатных сундуков и руин, артефакты только
  из лавки. `gold_sources` — стартовое золото, золото руин, продажа
  драгоценностей; доход по дням не считается.

Оптимистичные допущения: одно повышение за бой и потеря опыта сверх порога
не учитываются; последний XP каждого порога должен прийти из боя.

### archive

MAP-Elites-архив по осям: число контролёров, урон за раунд (корзины
`--damage-bin`), лишние жизни k (0–3+), стоимость в золоте (`--gold-bin`).
В каждой ячейке — лучшая по формуле тактика; цепь Маркова считается для
`--chain-top` элит. Полный перебор кандидатов заполняет архив сразу,
поэтому мутации не нужны.

### simulate

Обобщение ручных скриптов:

- состояние строится через `reset` + `replace` (бойцы, уровни, весь
  инвентарь карты, все зелья), затем `_refresh_equipment` и полное HP; герой
  берёт свою стартовую строку каталога (навыки и Мощь лорда);
- экипировка, отдых и зелья — настоящими действиями среды с проверкой маски
  (`equip_*`, `rest`, `potion_<вид>_<слот>`); раны стража — после отдыха;
- вход в бой — шаг направления с соседней клетки; `vmap` по ключам и
  `lax.while_loop` по решениям, одна компиляция на все тактики;
- скриптовая тактика: правила предметов героя (по приоритету; маска решает,
  какой слот подходит), предметы первого хода, копирование двойником,
  `defend_slots`, отступление при числе живых контролёров ниже
  `retreat_below_controllers`, лекари лечат самого раненого;
- проверка: каждая форма должна входить в `progression.used_ids`, иначе её
  способности не скомпилированы в эту карту и результат был бы ложным;
  превышение лидерства — предупреждение;
- отчёт `report.json`: победы, поражения, отступления, незавершённые бои,
  раунды, квантили HP стража, удары, предметы, HP после 1-го раунда,
  аналитика того же состава, правила, расхождения статической модели с
  `unit_stats` среды (`static_vs_env`) и запись одного боя (`--trace`).
  В папку копируются скрипт и `tactics.json`.

Компиляция кешируется в `results/guardian-lab/compilation-cache`.

## Модель и приближения экрана

Точные копии формул среды: рост уровней и бонусы героя, Мощь, пределы урона
(300, 400 у тяжёлых героев, без предела у поддержки), порядок зелий
(постоянные по одному виду, временные перемножаются до одного округления),
артефакты и знамя, вторичные характеристики (только форма и уровень: зелья,
заклинания, знамёна и артефакты их не меняют), бонус укрепления, предел брони
90%, урон с прибавкой 0…5 и итоговым пределом до вычитания целой поглощённой
части, пара бросков точности,
40-раундовый порог, шанс снятия по возрасту. `simulate` сверяет их с
`unit_stats` и записывает расхождения.

Приближения:

- удар стража бьёт всех по среднему из шести бонусов, без промаха 0,45% на цель;
  пограничные значения HP могут переходить в соседнее число ударов;
- «быстрый» боец — шанс ходить раньше стража не меньше 0,5 (сумма двух
  равномерных прибавок 0…10); смешанный порядок отмечается предупреждением;
- DoT — средняя доля активных раундов при обновлении каждый раунд
  (снятие 21% в возрасте 1), без отдельного состояния;
- предметы героя — не больше одного между ударами; ход, потраченный на
  предмет, не вычитается из урона;
- свита стража, лекари, призыватели, Фенрир, ведьмы на своих, лишний ход
  Сферы ярости, бегство от страха вне укрепления и превращение стража
  предметами в цепи не моделируются — для них нужен `simulate`;
- одноразовая защита стихии гасит только первый удар.

## Правила, на которых держатся тактики

Каждая тактика `screen`/`simulate` содержит поле `rules` с идентификаторами и
`unverified` — правила, не подтверждённые установленной редакцией. Полный
реестр — `RULES` в скрипте. Статусы: **original** — DBF/EXE, руководство или
проверка пользователя в игре; **reference** — только Python-референс;

## Исключения JAX для стражей

- Превращение: юниты Ведьма/Колдунья/Суккуб и артефакт Hag's Ring исключают
  стражей столиц (`number_grid.py` около строк 2645–2646,
  `number_grid_item_combat.py:103`). Сфера и талисман Ведьм и Сфера
  ликантропии исключения не имеют (`number_grid_battle_items.py`, ветки
  TRANSFORM и LYCANTHROPY) — несогласованность.
- Shatter исключён для стражей — совпадает с GImmuC Мизраэля.
- Заклинания и отдельные призывы карты не выбирают стража
  (`number_grid_casting.py:148`).
- Двойник не копирует стража (`copy_forbidden`, UNIT_CAT=8).
- Понижение формы (Сущий, Wight Blade) бессильно: у стража нет пониженной формы.
- Стражи не получают боевой опыт.
- `attack_class_immunities` из `units.json` среда не читает: действуют только
  перечисленные явные исключения.

## Раны между боями

`casting.finish_battle` сохраняет раны стража после победы или отступления
отряда, а отдых лечит его на REGEN юнита + 35% столицы (Мизраэль: 50 + 35 =
85% за ход, `number_grid_casting.py:rest`). Вход в бой стоит половину запаса
хода с ограничением остатком очков, поэтому по коду JAX за день возможны два
нападения: первое снимает часть HP и отступает, второе начинается с
оставшимся HP. `screen --wounds N` и поле `guardian_wounds` тактики оценивают
второй бой. Правило помечено открытым вопросом.

## Открытые вопросы для проверки в игре

Инструмент не запускает игру и IDA; ниже — что проверить пользователю.

1. **Урон по окаменевшему юниту.** Окаменить врага Инкубом и ударить
   бойцом: уменьшается ли HP. Если окаменевшие неуязвимы, тактики
   «контроль + урон» в JAX завышены, и правило среды нужно менять.
2. **Превращение стража.** Суккуб или Ведьма против стража столицы:
   превращение или «Иммунитет». В GImmuC у Мизраэля только Shatter; итог
   решает и несогласованность со сферами Ведьм и ликантропии.
3. **Порог 40 раундов.** Бой дольше 40 раундов: окаменяет ли Инкуб на 41-м;
   в IDA — ветка обнуления точности paralyze/petrify в установленном
   `Discipl2.exe` (сейчас — значение D2ModdingToolset по запросу пользователя).
4. **Страх по стражу.** Запрещено ли ему бегство (тогда короткий паралич).
5. **Заклинания по стражу.** Можно ли выбрать стража столицы целью урона или
   ослабления.
6. **Раны после отступления.** Отступить и напасть снова в тот же день:
   сохранились ли раны; сколько страж лечит за ход.
7. **Бросок точности.** Одно или два случайных числа (IDA): меняет все
   вероятности контроля.
8. **DoT и броня.** Снимает ли ожог Владыки полный урон по цели с бронёй 90.
9. **Усиления и вторичная атака.** С 19.10.2026 среда считает, что зелья и
   заклинания, как знамёна и артефакты, вторичную атаку не меняют
   ([ITEMS.md](ITEMS.md#potions-вторичная-атака)); Python-референс усиливал
   обе атаки. Проверка: тик ожога Владыки 5-го уровня (30) без бонусов, с
   Эликсиром энергии и со Знаменем мощи должен совпадать; доля окаменений
   Дьявола Бездны с Зельем точности — прежней (около 100 ударов на вариант).
