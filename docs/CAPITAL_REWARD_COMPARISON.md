# Default Capital: сравнение схем наград

Запрос пользователя от 16.10.2026: два независимых обучения по **20 млн переходов**,
сравнение качества и скорости. Пользователь отдельно выбрал одинаковую награду
Мизраэля и сравнение остальных наград. Это целевые обучения с явно заданным
бюджетом, не `--test-run` и не продолжения тестовых запусков.

## Условия

Одинаковые Default Capital, зелёный дракон, отсутствие событий, seed 42, 250 сред,
rollout 100, MLP [128,128], tanh, штатный PPO. Каждый запуск начинается с нуля;
GPU используется последовательно. Снимки карт отличаются только `reward_profile`,
`reference_preserve_target_reward` и `step_cost`. Размер наблюдения, действия,
начальные веса, исходники и пакеты проверяет `scripts/compare_capital_rewards.py report`.

Текущая схема описана в [DEFAULT_MAP.md](DEFAULT_MAP.md#capital).
Вторая использует существующий JAX-профиль `python_reference`, источники:
`C:/Disciples 2 python reference/Big_map/train_campaign.py:REWARD_CONFIG`,
`campaign_env.py`, `campaign_env_battle.py`, `campaign_env_territory.py`,
`campaign_env_economy.py`, `campaign_env_inventory.py`. Константы и SHA-256 этих
файлов сохраняются в `protocol.json` перед запуском. Правила профиля:
[REFERENCE_CAMPAIGNS.md](REFERENCE_CAMPAIGNS.md#награды).

В Python нет отдельной цели Capital с Мизраэлем. По выбранному пользователем
условию `reference_preserve_target_reward: true` сохраняет текущую тактическую
награду боя с целью: +1 за победу, +3 за цель и общий бонус
`5 × Σ max(уровень живого постоянного бойца на входе − 1, 0)`.
В этом бою не добавляются Python-бонусы за вход, активации, опыт, сохранность и
продвижение формы; дополнительной выплаты +8/+96 за цель и +6 за первое
вступление нет. Остальные бои используют выбранный профиль. Общий бонус Python
в конце эпизода `5 × доля побеждённых армий` сохраняется отдельно.

Это сравнение наград в общей JAX-среде. Исходный Python-движок не запускается;
геометрия, бои, допустимые действия, длительность шага и ограничения остаются
JAX-правилами. Используется существующая адаптация Python-профиля: история
посещений и некоторые флаги наград не входят в наблюдение; отдельные оригинальные
режимы full_party/dragon и их специфические бонусы здесь не включаются.

| Событие вне целевого боя | Текущая схема | Python-профиль |
|---|---:|---:|
| Вход в обычный бой | 0 | +0,25 |
| Победа над обычным отрядом | +1 | +4,5, бонусы опыта и сохранности |
| Продвижение формы / первые уровни героя | 0 | 3 + 0,5 × новый уровень |
| Найм с новым рекордом заполненного лидерства | +3 | +12 |
| Лечение за HP в пределах боевого бюджета | +0,0001 | +0,01 |
| Новая клетка, без объекта, до стоимости решения | +0,01 | +0,091, затем −0,002 за направление |
| Повторное посещение / возврат A→B→A | 0 | до −0,08 / ещё −0,03 |
| Постройка здания | +0,05 | 0 |
| Очистка руин сверх победы | +0,25 | +1 |
| Временный эликсир из сундука / применение | 0 / 0 | +4 / +2 |
| Обычная активация в бою | 0 | +0,0025 |
| Отдых | −0,001 × оставшиеся очки | −0,01; ещё −0,20 при оставшихся очках |
| Обычное решение | −0,001 | 0 |
| Поражение кампании | −1 | −6 и −0,25 за завершение боя |
| Таймаут | 0 отдельно | −8 |
| Конец эпизода | 0 отдельно | +5 × доля побеждённых армий |

Общий штраф незаполненного лидерства −0,05 за свободное очко на решение
сохранён. Награда за воскрешение, исследование и применение заклинаний также
общая. Коэффициенты Python-профиля делают обычные победы и развитие заметнее,
но положительная награда за незавершённые боевые активации и восстановление
может конкурировать с конечной целью. Это гипотезы до измерения качества.

## Измерение

Перед обучением `scripts/validate_reference_maps.py` проверяет на CUDA загрузку,
геометрическую достижимость, reset, REST, допустимый подход к Мизраэлю и начало
боя. Это структурная проверка проходимости, не доказательство победного маршрута.
Данные проверок не передаются агенту.

Каждый learner измеряется целиком с ожиданием GPU; rollout, PPO и сбор метрик
включены. Компиляция, логирование, отчёты эпизодов, сохранение и оценка учитываются
отдельно. Итоговая оценка: 1024 эпизода argmax и 1024 с выборкой, seed 1042,
только финальные веса. Промежуточная лучшая модель не выбирается.
Качество: доля побед, достижение Мизраэля, лучший урон ему за эпизод и число
побеждённых армий. Сырые суммы наград между профилями не сравниваются как качество.
Один seed даёт предварительный результат, а не доказательство устойчивого преимущества.

Замер скорости не изолирует стоимость формулы награды от изменения траекторий.
Python-профиль дополнительно обновляет историю посещений 2500 клеток, считает
сохранность и продвижения на внутренних боевых активациях, проверяет пороги HP
после каждого решения. В интервале 13–14 млн переходов текущая схема выполнила
293899 боевых активаций, Python — 361104; автоматических активаций было
117669 и 146684, завершений эпизодов — 754 и 1355 соответственно.
Скорость этого интервала: 21498,74 и 17227,92 перехода/с. Эти счётчики показывают
различие нагрузки; они не измеряют отдельный вклад каждой операции в замедление.
Источники чисел — сохранённые `charts.jsonl` обоих запусков, строка 14 млн.

Каталог запуска: `results/capital-rewards-20m-20261016/`; в нём карты, протокол,
проверка проходимости, папки `current` и `python`, затем `comparison.json` и
`comparison.md`. Графики — `tracking.json` каждого запуска.

Подтверждающие расширенные тесты: `stoix/tests/number_grid_capital_reward_comparison_test.py`.
Проверяют одинаковую целевую награду, отсутствие второй целевой выплаты,
различие обычных побед и валидацию переключателя. В `core` не добавлены.
Регрессионные тесты без отдельного запроса не запускаются.

## Результат 20 млн + 20 млн

Оба запуска завершены на GTX 1660 Ti. Совпали конфигурации PPO, начальные веса,
исходники и пакеты. Learner: текущая схема **29575,37 перехода/с** за 676,24 с;
Python — **17892,52 перехода/с** за 1117,79 с (**−39,50% скорости**).
Компиляция PPO отдельно: 63,86 / 65,62 с. Полное время запуска с оценкой,
отчётами, сохранением и трекером: 1069,36 / 1561,57 с.

| Финальная оценка | Текущая | Python |
|---|---:|---:|
| Победы, argmax / sampled | 0/1024 / 0/1024 | 0/1024 / 0/1024 |
| Вступили в бой с Мизраэлем, argmax / sampled | 0 / 28 | 0 / 2 |
| Максимальный урон Мизраэлю, sampled | 1,44% | 0% |
| Побеждено отрядов в среднем, argmax / sampled | 28,04 / 31,98 | 29,51 / 30,47 |

По основной цели победителя нет: обе схемы пока не обучили убийство Мизраэля.
Для продолжения разумнее оставить текущую схему: она быстрее и в sampled-оценке
чаще доводит агента до цели. Преимущество в обычных боях смешанное и небольшое:
Python впереди в argmax, текущая — в sampled. Это вывод об этом запуске с одним
seed, а не доказательство превосходства каждого отдельного коэффициента награды.
Python-профиль сохранён только в экспериментальной карте; награды Default Capital
по умолчанию не переключались.

Полный отчёт: `results/capital-rewards-20m-20261016/comparison.md`, машинные данные:
